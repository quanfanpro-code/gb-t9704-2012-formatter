# 普通材料版式回归修复设计

## 目标

在不重建文档内容、不破坏超链接及复杂对象的前提下，修复无文号多行标题、复杂段落和表格的版式回归，并让最终检查验证实际排版结果。

## 方案比较

### 方案一：Open XML 原位修复（采用）

只修改段落、运行和单元格的显示属性，不替换文字，不重建复杂结构。复用现有流水线、结构分析器和校验器。

- 实现成本：中
- 内容损失风险：低
- 兼容性：沿用现有 Open XML 处理方式
- 测试难度：低，可直接检查节点、关系和属性
- 可逆性：高，改动集中在现有服务

### 方案二：重建段落和表格

提取文字后重新生成段落和表格。版式统一最直接，但会丢失或重建超链接、批注、域、书签、修订及嵌入对象。

- 实现成本：高
- 内容损失风险：高
- 兼容性：差
- 测试难度：高
- 可逆性：中

### 方案三：Word COM 二次排版

Open XML 生成后，再调用 Microsoft Word 修改样式和分页。

- 实现成本：高
- 内容损失风险：中
- 兼容性：依赖本机 Word 和桌面会话
- 测试难度：高
- 可逆性：低

## 组件设计

### 标题识别

`GovStructureAnalyzer` 增加“文档标题样式”的独立识别，不再要求先出现标准公文文号。首段使用 Word `Title`/“标题”样式时，将其识别为标题区；普通 `Heading 1` 仍按正文层次标题处理，避免把“问题二”“发行人回复”误并入标题区。

标题格式沿用现有规则：二号方正小标宋简体、居中、无首行缩进。段内手动换行保留，每一行随段落居中，不再按正文两端对齐。

### 安全文字格式化

`GovOpenXmlHelper` 提供统一的“可格式化文字运行”枚举：

- 包含普通可见文字的直接运行参与格式化。
- 超链接、书签区间、批注区间、修订容器中的可见文字运行参与格式化。
- Drawing、文本框、公式及嵌入对象内部运行不处理。
- 不删除、不移动、不重建任何节点，不修改超链接关系或字段指令。

`GovParagraphService` 先按段落语义设置行距、缩进和对齐，再格式化安全文字运行。复杂结构只阻止破坏性重写，不再阻止显示属性调整。

### 表格格式化

`GovTableService` 恢复非破坏性的显示格式处理：

- 不删除空行空列，不改写数字，不改行列、合并关系和宽度。
- 单元格垂直居中。
- 段落使用固定行距并清除正文首行缩进。
- 第一列左对齐，其余列居中。
- 可见文字使用小四号仿宋，西文使用 Times New Roman。

### 版式结果校验

`GovValidationService` 在 OpenXML Schema 和页面参数检查后增加版式一致性检查：

- 已识别标题必须居中、无首行缩进，并使用二号标题字号。
- 普通正文及复杂段落的可格式化文字必须使用三号正文字号。
- 表格可格式化文字必须使用小四号字号。
- 校验只检查本程序负责的可见文字，不检查图片、公式或嵌入对象内部格式。

流水线把检查结果写入 `FORMAT_CONSISTENCY / 版式一致性` 审计记录。程序先完成格式化，再执行校验；校验不是人工复核的替代品。

## 数据流

1. 打开输入 DOCX 的临时副本。
2. 分析标题、文号、正文层次和其他公文要素。
3. 原位设置段落属性及安全可见文字属性。
4. 原位设置表格单元格、段落和安全可见文字属性。
5. 处理页眉、页脚和正式公文专属要素。
6. 重新打开候选文件，执行结构、页面和版式一致性校验。
7. 校验通过后发布输出并写审计 JSON。

## 错误处理

- 输入、输出和临时文件规则保持不变。
- 发现 OpenXML 结构错误时继续阻断发布。
- 发现本程序负责的版式属性未写入时，视为内部处理失败，不把未排好的文件伪装成正常成稿。
- 不可安全修改的对象本体保持原样；只要其外部段落和可见文字达到规则，不产生人工复核提示。

## 测试策略

1. 无文号、多行、`Title` 样式标题：验证标题识别、居中、二号字号和无首行缩进。
2. 含超链接正文：验证文字、关系和地址保持，直接文字与链接文字均为三号仿宋。
3. 含书签或图片段落：验证对象数量保持，普通可见文字完成格式化。
4. 表格：验证文字数字、行列数、合并及宽度保持，小四字号和对齐生效。
5. 版式门禁：构造不符合规则的候选文档，验证版式检查能够报错；正常输出的审计记录包含通过结果。
6. 运行全部测试、Release 构建、格式检查及真实样本 Word 原生渲染。

## 迁移与回滚

不修改文件格式和公共请求接口，无数据迁移。若需回滚，可恢复本次修改的结构分析、段落、表格和校验服务；原始输入文件始终不受影响。

## ADR

本次方案沿用既有 Open XML 架构，不引入难以逆转的新技术或跨模块协议，因此不新增 ADR。
