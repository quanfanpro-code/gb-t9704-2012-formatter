# 批处理互鉴方案

选择在原项目局部补齐：命名规则按本库真实输出格式识别；请求携带可选 CancellationToken，主流程、段落、分节和正式公文循环检查取消，正式发布前再次检查。取消结果使用 CANCELLED，沿用失败副本保留方式。

另一方案是提取两仓库共用框架，会增加跨库依赖和发布工作，本期不采用。仅加强界面按钮而不传入流水线不能解决大文件等待问题，也不采用。

保持现有 API 兼容：新增参数有默认值；布局常量不改。界面单文件与文件夹使用同一个过滤函数，取消状态不显示为普通失败。

验证先运行新增用例确认现有缺口，再随最终全套测试检查回归。不增加 Word 样本或安装依赖。回滚使用外部校验备份或对应 Git 提交。无难以逆转的架构变化，不单独建立 ADR。
